Croncord Ecosystem & Background Daemon

Overview of architecture, anti-detection mechanisms, and terminal deployment options.

Anti-Detection Jitter

Croncord uses randomized delay jitter (default 1-10 minutes) before firing. Discord's automated pattern algorithms detect check-ins that trigger at the exact zero second mark every day. Jitter breaks the temporal signature and preserves account longevity.

Human Typing Simulation

Before message submission, Croncord broadcasts typing indicators (`sendTyping()`) with human-calibrated duration (1.5s base + 100ms per character) simulating natural keystroke pacing.

Android (Termux No-Root)

Croncord includes full support for unrooted Android devices running Termux. The daemon acquires a wake lock through termux-wake-lock to avoid sleep-state suspension and hooks into ~/.termux/boot/ for auto-resurrection on reboot.

Server Health Status Legend

Understanding server states, uptime, and conflict warnings

Running Normal / Healthy

The server profile is actively monitored. All configured daily attendance routines are queued and the most recent execution completed successfully.

Failed Attention Required

The most recent attendance check-in failed to execute. Check the Live Activity Console for the specific Discord error (e.g. invalid user token, deleted channel, missing permissions, or rate limit).

Disabled Monitoring Paused

This server profile is paused by the user. No scheduled messages or reactions will be posted until you click the play button or use bulk actions to re-enable it.
